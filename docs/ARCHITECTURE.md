# Архитектура универсальной ветки

Развитие исходной версии 0.4.2. Пользовательский сценарий описан в
`UNIVERSAL_PREVIEW.md`, подключение следующего движка — в `ADDING_ANALYZERS.md`.

## Слои

- `app/gui` — отображение, drag-and-drop, очередь и фоновые задачи PySide6.
  `FindingsExplorer` объединяет поиск, исходное значение, пояснение и отметку эксперта.
- `app/core` — сценарий исследования, целостность, сигнатуры, SQLite, конфигурация
  и логирование.
- `app/models` — типизированные доменные модели проекта, файла, запуска и факта.
- `app/adapters` — изолированный запуск каждого внешнего инструмента через
  `subprocess` с `shell=False`; Poppler, JHOVE, veraPDF и PDFBox не разделяют
  команды или состояние друг с другом.
- `app/analyzers` — встроенные read-only анализаторы PDF, OOXML, изображений, ZIP и противоречий.
- `app/reporting` — независимые экспортёры отчётов.
- `app/resources` — локализация, сведения о лицензиях и разрешённые к включению
  сценарии сторонних инструментов.

Поток данных:

```text
GUI / наблюдаемая папка -> JobQueue (SQLite) -> QueueDaemon
                         -> отдельный процесс (spawn) на файл
                         -> ForensicsService -> EvidenceWorkspace -> рабочая копия
                      |-> встроенный анализатор формата
                      |-> адаптеры внешних инструментов
                      |-> отрисовка и diff реконструированных ревизий
                      |-> MetadataConflictDetector
                      |-> AnalysisRepository (SQLite)
                      `-> AnalysisResult -> GUI / HTML / JSON / DOCX / ZIP
```

## Гарантия неизменности оригинала

`EvidenceWorkspace` открывает оригинал только на чтение, потоково считает три
хеша, копирует байты в отдельный каталог и сравнивает SHA-256. Анализаторы получают
только путь к рабочей копии. Перед каждым внешним адаптером и после набора запусков
хеш рабочей копии проверяется повторно. В конце также повторно проверяется хеш
оригинала, чтобы заметить внешнее изменение во время исследования.

## Добавление нового формата

1. Добавить значение в `FileKind` и сигнатурное правило в `core/formats.py`.
2. Создать read-only анализатор с методом `analyze(Path) -> list[Finding]`.
3. Подключить анализатор в `ForensicsService`.
4. Проверить отображение общих фактов и добавить русские подписи; отдельная
   вкладка нужна только для специального представления, например дерева PDF-объектов.
5. Добавить unit-тесты сигнатуры, повреждённых данных и лимитов ресурсов.

Реестр `PROFILES` задаёт тип, семейство, MIME, расширения и честное описание
области проверки. Тип выбирается по содержимому, а не по расширению. Для неизвестного
типа остаются базовые сведения и ExifTool. Интерфейс отображает общие `Finding`,
поэтому новому формату обычно не нужна новая вкладка.

## Очередь и восстановление

`JobQueue` хранит задания в отдельной `queue.sqlite3`. Producer может добавлять
задания из другого процесса. Только владелец файловой блокировки выполняет их и
возвращает оставшиеся `running` в `pending` после перезапуска. Взятие задания
использует `BEGIN IMMEDIATE`. Версия источника закрепляется размером и mtime.

До запуска выделяется постоянный ID результата. Дочерний процесс пишет результат
под этим ID. Если процесс завершился между коммитом отчёта и подтверждением
очереди, восстановление находит сохранённый результат и подтверждает его без
повторного исследования. Явный повтор создаёт новый ID результата.

`FolderScanner` пропускает временные файлы, ссылки и собственное хранилище.
Он ждёт две одинаковые версии stat и минимум три секунды стабилизации.
Дедупликация сохраняется в SQLite между перезапусками.

`analyze_isolated` использует multiprocessing spawn. В родительский процесс
передаются прогресс и ID результата. Отмена сначала кооперативная, через три
секунды процесс останавливается; общий таймаут завершает зависший парсер.
`CommandRunner` запускает аргументы без shell, пишет stdout/stderr во временные
файлы и ограничивает объём захвата. Это изоляция сбоев, не системная песочница.

## Целостность отображения и экспорта

Повторяющиеся теги ExifTool сохраняются отдельными фактами с номером в JSON;
их нельзя свести обычным JSON-dict с потерей предыдущих значений. EXIF rational
сохраняет числитель и знаменатель. Сравнение различает расположения полей.
В Windows имя файла для ExifTool передаётся через UTF-8 stdin по протоколу
argfile, чтобы сохранить кириллицу и другие Unicode-символы. Точный ввод сохранён
в `ToolRun.parsed_result.stdin_utf8`, технических подробностях и отчётах.
Дата без часового пояса сохраняет нормализованную строку, но не получает
абсолютный timestamp. Выдержка и длительность не считаются датами событий.

Таблицы показывают сокращённый текст, исходное значение — в панели подробностей.
Большое значение можно экспортировать отдельно. HTML/DOCX включают источники,
расположение, экспертные отметки и область проверки; JSON сохраняет полную модель.
Экспорт пишет в уникальный временный файл рядом с назначением и публикует его
атомарной заменой. Назначение проверяется на совпадение с оригиналом/рабочей
копией, включая жёсткие ссылки. Неуспешный экспорт сохраняет прежний отчёт.

## Добавление внешнего инструмента

1. Реализовать отдельный `ToolAdapter`.
2. Передавать аргументы списком, никогда не строкой для shell.
3. Использовать `CommandRunner`, чтобы зафиксировать команду, версию, время,
   длительность, stdout, stderr, exit code и timeout.
4. Вернуть нормализованные `Finding` отдельно от необработанного вывода.
5. Для локальной preview-сборки обновить фактический инвентарь через
   `prepare_preview_build.py`. Если бинарник включается в распространяемый релиз,
   добавить его состав, лицензию и источник в релизный compliance-процесс;
   сохранённый исторический SBOM 0.4.2 не описывает новые сборки.

## Поиск по проекту

`search_project` читает сохранённые факты из SQLite в отдельном потоке.
Поиск фрагмента использует Unicode casefold и русские подписи полей. Результат
содержит ID исследования и ID факта: открытие не требует повторного разбора файла.
Фильтр проекта применяется в SQL, включая отдельную группу исследований без
проекта. Ограничение числа строк и времени возвращает явный признак частичного
результата. Это линейный поиск сохранённых полей; полнотекстовый индекс пока
не реализован. Боковая панель отдельно читает краткие сведения об исследованиях.
