# Область применения и ограничения

- Поддерживаются PDF, PPTX, DOCX/XLSX, изображения, медиа и ZIP.
  Перечень форматов — в `release/REQUIREMENTS-RU.txt`. Глубина проверки различается:
  успешная базовая карточка неизвестного формата не означает полный анализ.
- Сигнатуры определяют предполагаемый контейнер. MIME у семейств MP4 и Matroska
  является профилем контейнера; он не доказывает наличие видеодорожки. Повреждённый
  или специально неоднозначный файл требует сопоставления нескольких инструментов.
- Word: сохранённые комментарии и исправления в основном документе, колонтитулах,
  сносках. Список исправлений ограничен 5000 записями с отдельным полным счётчиком.
  История принятых/удалённых правок и современные threaded comments не восстанавливаются.
- Excel: свойства, внешние связи и видимость листов. Значения ячеек и формулы
  не пересчитываются, бинарные XLS/XLSB и старые DOC не разбираются этим профилем.
- Наличие VBA фиксируется по частям пакета DOCX/XLSX; код не исполняется и не
  декомпилируется. Отсутствие перечисленных частей не является проверкой на вредоносность.
- Изображения: доступные метаданные, без доказательства монтажа. Предпросмотр
  только первого кадра, с ориентацией EXIF; изображения более 24 Мп не декодируются
  для предпросмотра. Большие двоичные поля Pillow ограничены 4096 байтами с пометкой.
  Дробные EXIF-значения сохраняют числитель и знаменатель. HEIC/AVIF/RAW не имеют
  отдельного встроенного профиля; доступные данные может извлечь ExifTool.
- ZIP: каталог без извлечения; CRC и даты берутся из каталога, контроль содержимого
  записей не выполняется. Содержимое вложенных архивов не исследуется.
- Демон — локальный процесс, не установленная служба Windows. При закрытии GUI
  его обработчик завершается; для постоянной работы нужен `--watch`.
- Дедупликация наблюдаемой папки использует путь, размер и mtime, проект и режим.
  Изменение байтов с сохранёнными размером и mtime требует явного повторного импорта.
  Файлы принимаются после стабилизации; позднее изменение останавливает старое задание.
- На одно хранилище допускается один исполнитель очереди. GUI другого экземпляра
  может просматривать задания; управлять паузой/отменой чужого процесса он не может.
- Изоляция процессом защищает интерфейс от зависания парсера. Она не ограничивает
  права процесса как OS sandbox и не вводит жёсткий лимит RAM. Общий таймаут действует
  для очереди; прямой `--analyze` ограничивает внешние инструменты, но не весь сценарий.
- Параметр таймаута внешней утилиты не включает до 15 секунд определения её версии.
  Вывод ограничен 32 МиБ на поток; превышение отмечает запуск как незавершённый.
- DOCX-таблицы сокращают значения длиннее 6000 символов с пометкой; полные значения
  доступны в JSON. HTML и JSON не сокращают сохранённые поля. Неизвестный часовой
  пояс явно отмечается; такая дата не сравнивается с датой с известным поясом
  для вывода о порядке создания/изменения.
  Даты без пояса не получают абсолютный timestamp и идут после дат с известным
  поясом; внутри этой группы сохраняется порядок источников, а не выдуманная
  общая хронология. Повторный анализ нужен, чтобы применить это правило к ранее
  сохранённым исследованиям.
- Восстановление PDF-ревизии создаёт точный байтовый префикс до соответствующего
  `%%EOF`. Для тяжело повреждённых файлов или нестандартных сохранений потребуется
  ручная проверка и сопоставление с QDF.
- Физический индексатор показывает обычные косвенные объекты и их точные смещения.
  qpdf JSON дополнительно разворачивает объекты внутри `/ObjStm`, но для них нет
  отдельного физического смещения в исходном файле; подробности доступны в QDF-копии.
- Криптографическая целостность подписи и цепочка сертификата проверяются офлайн.
  Сетевое получение OCSP/CRL отключено, поэтому актуальный статус отзыва может быть
  неизвестен. Недоверенная цепочка не равнозначна нарушенной криптографической
  целостности.
- Содержимое зашифрованного PDF без предоставленного пароля может быть недоступно
  отдельным анализаторам; структурные факты и сырые результаты всё равно сохраняются.
- Автоматические правила только выделяют технические расхождения. Они не делают
  вывод о подделке, авторстве или юридической действительности подписи.
- JHOVE и veraPDF проверяют форматную корректность и заявленные профили стандартов.
  Ошибка PDF/A/PDF/UA не означает фальсификацию и показывается как отдельное
  техническое наблюдение.
- Визуальное сравнение охватывает первые 25 страниц каждой реконструированной
  ревизии при 96 DPI. Пиксельное отличие показывает изменение отображения, но не
  устанавливает автора, время или намерение правки.
- В прежней релизной Windows-сборке Poppler 26.02.0 отсутствует `pdfsig`; подписи продолжают
  независимо проверяться встроенным ByteRange-анализатором, pyHanko и pdfcpu.
  Текущая локальная preview-сборка не включает Poppler и другие внешние CLI;
  доступность каждого метода зависит от установленных инструментов.
- Имена Author/Creator, XMP History, DocumentID и следы программ являются заявленными
  или контекстными признаками. Установление фактического владельца требует независимых
  материалов: носителя, учётной записи, переписки, журнала системы или валидной подписи.
- Подписанный EXE создаётся только при наличии пользовательского Authenticode-
  сертификата и Windows SDK `signtool.exe`.
- Автообновление требует опубликованного HTTPS-манифеста и установщика с известным
  SHA-256; без URL приложение не обращается в сеть.
