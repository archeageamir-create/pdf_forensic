# Автономная сборка для Windows

Пользователю нужен один ZIP. Его нужно распаковать целиком и открыть EXE.
Устанавливать Python, Java, Perl или инструменты анализа не требуется.
Программа не скачивает их при первом запуске. Папку `_internal` нужно оставить
рядом с EXE; переносить программу можно вместе со всей папкой.

## Что входит

| Компонент | Версия | Для чего нужен |
| --- | --- | --- |
| Python, Qt/PySide6 и библиотеки приложения | В `BUILD_INVENTORY.json` | Окно программы, встроенные проверки, отчёты |
| ExifTool с полным комплектом Perl | 13.59 | Метаданные файлов |
| qpdf | 12.3.2 | Структура и объекты PDF |
| pdfcpu | 0.13.0 | Проверки, подписи, формы и вложения PDF |
| Poppler, DLL и таблицы кодировок | 26.02.0 | Текст, шрифты, изображения и отрисовка версий PDF |
| ffprobe, сборка АНСЭ с заменяемыми DLL | 8.1.2 | Контейнеры и дорожки аудио/видео, включая сжатые заголовки |
| Eclipse Temurin Java JRE | 21.0.11+10 | Запуск трёх Java-инструментов ниже |
| JHOVE с модулями и настройками | 1.34.0 | Проверка PDF-hul |
| veraPDF Greenfield | 1.30.2 | Проверка соответствия стандартам и сведения о PDF |
| Apache PDFBox | 3.0.8 | Текст, XMP и исследовательская копия PDF |
| PDFiD / pdf-parser и их EXE-адаптер | 0.2.10 / 0.7.14 | Низкоуровневые проверки PDF |

`ffmpeg.exe` и `ffplay.exe` не используются приложением. Для чтения медиаданных
включён самостоятельный `ffprobe.exe`. Word не требуется для создания DOCX-отчёта.
Для чтения и редактирования сохранённого отчёта пользователь выбирает привычную программу.

## Как собрать

На компьютере разработчика нужны Python 3.12 и окружение проекта:

Сначала восстановите комплект исходников и готовый архив ffprobe по
[инструкции](DEPENDENCY_SOURCES.md). Его можно пересобрать нашим сценарием
через MSYS2 UCRT64. Остальные закреплённые пакеты скачивает сценарий подготовки.

```powershell
.\setup.ps1
.\build-preview.ps1
.\.venv\Scripts\python.exe scripts\package_preview.py
```

При первой сборке скачиваются архивы из закреплённого списка
`compliance/runtime-dependencies.lock.json`. Там записаны точные адреса, версии
и SHA-256. Загрузки сохраняются в `.downloads/runtime`; повторная сборка использует
проверенные копии. Скрипт не копирует произвольные установленные на компьютере инструменты.

Подготовка зависимостей отдельно:

```powershell
.\.venv\Scripts\python.exe scripts\prepare_runtime_dependencies.py --download
.\.venv\Scripts\python.exe scripts\prepare_runtime_dependencies.py --verify-only
```

Распаковка происходит внутри проекта. Java-установщики работают только на этапе
сборки, с отдельной временной папкой и профилем. На компьютер пользователя попадают
готовые файлы. Прежний комплект при переподготовке сохраняется в `build/runtime-previous-*`.

Оба PyInstaller-spec используют один и тот же обязательный комплект. Сборка
останавливается при отсутствующем или изменённом файле. DLL движков остаются в их
собственных папках; они не подменяют библиотеки Qt. `package_preview.py` повторно
проверяет все файлы инструментов, код приложения, PDF-руководство и учебные примеры.

## Как проверяется перенос

```powershell
.\.venv\Scripts\python.exe scripts\verify_preview_archive.py --output .verification\standalone-test --files 14
```

Проверка распаковывает архив в другой каталог с кириллицей, сверяет SHA-256 файлов,
запускает настоящий GUI и очередь. Затем запускает EXE с PATH, содержащим только
Windows, и отдельными пустыми папками USERPROFILE, APPDATA и LOCALAPPDATA. Проверяются все 11 инструментов, полный
анализ PDF с обновлением и отрисовкой двух версий, JPEG, WAV, DOCX и четыре формата
отчёта. Пути всех запускаемых движков должны находиться внутри распакованной программы.
Хеши исследуемых образцов после работы должны остаться прежними.
Сам комплект инструментов также сверяется до и после исследования. Настройки
veraPDF хранятся в рабочей папке, а не рядом с его JAR-файлами; программа не должна
записывать их в каталог своей установки.

Это изоляция путей и профиля на машине сборки, а не запуск в отдельной чистой Windows-VM.

Проверить инструменты вручную можно кнопкой «Проверить установку». Для сохранения
диагностики готовая EXE также понимает:

```powershell
.\DocumentForensicInspectorPreview.exe --check-tools --output tools.json
```

Если хотя бы один инструмент не запустился, команда возвращает код 2. Ошибка
исследования не превращается в успешный результат. Например, для veraPDF 1.30.2
отчёт о признаках читается в XML: его JSON-сериализатор ломается на `lowLevelInfo`.
Сохраняются полный исходный XML и совместимая JSON-обёртка, оба входят в ZIP-отчёт.
Изображения версий PDF сначала создаются в короткой временной папке, затем
переносятся в исследование. Это обходит ограничение PNG-модуля Poppler на длину
пути Windows. Пустой результат отрисовки не считается успешным.

## Перенос настроек и состав поставки

Стандартные пути к движкам не привязываются к папке компьютера разработчика.
При переносе или обновлении прежние пути к встроенным движкам пересчитываются.
Путь к инструменту, явно выбранному пользователем вне папки программы, сохраняется.
Если встроенный инструмент пропал, EXE сообщает об этом, а не подставляет другую
версию из системного PATH.

Точные файлы движков и их хеши находятся в
`_internal/app/resources/binaries/RUNTIME_MANIFEST.json`. Общий состав архива —
в `PREVIEW_MANIFEST.json`. Лицензии и уведомления поставщиков сохранены рядом
с инструментами и в `_internal/app/resources/licenses`; адреса исходных проектов
и сведения о предоставлении исходников находятся в `compliance` и `SOURCE_OFFER.md`.
