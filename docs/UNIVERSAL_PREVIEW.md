# Универсальная лаборатория файлов

Это рабочее расширение Document Forensic Inspector 0.4.2. Основной сценарий:
добавить файл → прочитать обзор → открыть интересующий факт → сохранить отчёт.
В обычном режиме видны обзор, результаты, хронология, выводы эксперта и очередь.
Переключатель технических деталей открывает прежние инструменты исследования PDF.

## Запуск

На подготовленном компьютере дважды щёлкните по `Launch.vbs` в корне проекта.
При первом запуске исходников выполните `setup.ps1` с Python 3.12 или новее.
Сценарий создаёт `.venv` и устанавливает зависимости только туда.

Для самостоятельной EXE выполните `build-preview.ps1`. Открывайте
`dist/DocumentForensicInspectorPreview/DocumentForensicInspectorPreview.exe`.
Вся папка рядом с EXE нужна для работы; перенос одного EXE недостаточен.
Эта локальная тестовая сборка содержит Python, Qt и библиотеки приложения.
Внешние CLI-движки в неё не включены. Их пути и фактические версии показывает
окно проверки инструментов. Инвентарь сборки: `_internal/app/resources/BUILD_INVENTORY.json`.
Инвентарь окружения включает также пакеты сборки; он не утверждает, что каждый
их модуль попал в EXE. Релизный SBOM 0.4.2 в исходниках сохранён отдельно.

Архив для переноса собирается командой
`.\.venv\Scripts\python.exe scripts\package_preview.py`. Она проверяет совпадение
исходников приложения с инвентарём EXE, добавляет SHA-256 каждого файла и проверяет
ZIP. Распакуйте `DocumentForensicInspectorPreview-Windows.zip` целиком.
Исходный код отдельно архивируется через `scripts\create_public_source_archive.py --preview`.

## Что можно исследовать

| Формат | Что доступно |
| --- | --- |
| PDF | Прежний анализ метаданных, структуры, ревизий, подписей, вложений и независимые CLI-проверки |
| PPTX | Свойства, заметки, комментарии, скрытые слайды, связи и встроенные объекты |
| DOCX, DOCM | Свойства OOXML, комментарии, сохранённые исправления, внешние связи, перечень VBA и вложенных объектов |
| XLSX, XLSM | Свойства OOXML, листы и их видимость, внешние связи, перечень VBA и вложенных объектов |
| JPEG, PNG, TIFF, GIF, WebP, BMP | Размеры, цветовой режим, доступные EXIF/GPS, данные Pillow и ExifTool, уменьшенный первый кадр |
| MP4, MOV, MP3, WAV, FLAC, OGG, MKV, AVI | Базовая идентификация; ffprobe и ExifTool дают контейнер, потоки, теги и технические свойства |
| ZIP | Каталог записей, размеры, заявленные CRC, флаги шифрования и необычные пути; без извлечения |
| Другой файл | Хеши, размер, первые байты, доступные данные ExifTool и явная пометка ограниченной проверки |

Тип определяется по сигнатуре и структуре ZIP. Несовпадение расширения с
определённым типом показывается как наблюдение. Идентификация контейнера сама
по себе не подтверждает его исправность. Базовая карточка не означает полный
разбор неизвестного формата.

## Как читать результаты

1. Добавьте один или несколько файлов кнопкой, сочетанием Ctrl+O или перетаскиванием.
2. В обзоре проверьте тип, область проверки, итог выполненных инструментов и наблюдения.
3. В «Результатах» ищите автора, программу, дату, GPS или конкретное значение.
   Фильтр «Требует внимания» оставляет расхождения, диагностику и факты для проверки.
4. Выберите строку: ниже появятся исходное значение, источник, расположение и пояснение.
   Большое значение можно сохранить целиком в JSON.
5. Поставьте экспертную отметку и выберите, включать ли факт в отчёт. Заметки сохраняются автоматически.
6. Экспортируйте JSON, HTML, DOCX либо ZIP с манифестом SHA-256, отчётами и артефактами.

Кнопка «Поиск по проекту» (Ctrl+Shift+F) ищет сразу во всех сохранённых
результатах выбранного проекта, включая русские значения и названия полей.
Двойной щелчок открывает нужный файл и конкретный факт. Первые 200 совпадений
показываются с источниками. Если достигнут лимит 5 секунд, частичный поиск явно
помечается. Поиск выполняется в фоне и не запускает повторный анализ файлов.

Имена авторов, даты, координаты и следы программ — значения, заявленные в файле.
Приложение не объявляет документ поддельным на основании одного признака.
Отсутствующая утилита, её ошибка и полностью выполненная выбранная проверка
показываются раздельно. «Быстрый» режим не запускает весь набор PDF-инструментов.

## Очередь и наблюдаемые папки

Во вкладке «Очередь» можно увидеть задания, открыть результат, отменить задание
или повторить неудавшееся. Пауза останавливает взятие следующих заданий;
текущий анализ продолжается, пока его отдельно не отменить.

В «Наблюдаемых папках» выберите папку и режим. Привязка к проекту фиксируется
при добавлении и отображается в списке; последующее переключение проекта её
не меняет. Вложенные папки включаются отдельной опцией.
Новый файл принимается после двух наблюдений с неизменными размером и временем
модификации и не менее трёх секунд ожидания. Служебные и временные файлы,
ссылки и каталоги самого приложения пропускаются.

Повторное сканирование не создаёт дубликат той же версии файла. Если размер или
время изменились, создаётся новое задание. Преднамеренное сохранение другого
содержимого с теми же размером и временем автоматически не обнаруживается.
Для повторного исследования используйте явный повтор/полную проверку.

После закрытия GUI встроенный обработчик прекращается. Для непрерывной работы
без окна запустите отдельный процесс:

```powershell
.\run.ps1 --watch "C:\Evidence\Inbox" --recursive --mode quick
# Ctrl+C завершает обработчик; активное задание остаётся для возобновления.
.\run.ps1 --drain-queue
# Отдельное хранилище, например для тестов:
.\run.ps1 --data-dir "C:\DFI-Test" --watch "C:\Evidence\Inbox" --mode quick
```

Папка наблюдения должна существовать и находиться вне хранилища приложения.
Для каждого хранилища работает один исполнитель. Второй GUI может просматривать
очередь и добавлять задания; пауза и отмена чужого активного процесса недоступны.
Режим демона здесь — длительно работающий локальный процесс; служба Windows и
автозагрузка пока не устанавливаются.

## Надёжность и границы

Оригинал открывается на чтение, инструменты получают рабочую копию. SHA-256
сравнивается до и после исследования; отчётом нельзя перезаписать оригинал
или рабочую копию. Контроль не отменяет изменения времени доступа файловой
системой и не заменяет аппаратный блокиратор записи при изъятии носителя.

Каждый файл очереди обрабатывается отдельным процессом. По умолчанию общий
лимит — 15 минут, внешний инструмент — 120 секунд, захват его вывода — 32 МиБ
на поток. Лимиты времени настраиваются. Это изоляция сбоев, а не системная песочница.
На один файл одновременно работает один процесс анализа. Очередь восстанавливает
задания после перезапуска и не дублирует уже сохранённый отчёт при восстановлении.

Локальные данные находятся в `%LOCALAPPDATA%/DocumentForensicsLab`:
`forensics.sqlite3`, `queue.sqlite3`, `cases`, `reports`, `settings.json`, журналы.
Файлы не отправляются в облако, внешние ссылки документов не открываются.

Подробные ограничения находятся в `docs/KNOWN_LIMITATIONS.md`. Распознавание OCR,
восстановление удалённых данных носителя, содержимое RAR/7z, старые бинарные
DOC/XLS и разбор кода макросов в этот этап не входят.
